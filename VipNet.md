# ViPNet — настройка офисной сети

Гайд по настройке координатора ОФИС-1 как VPN-шлюза, маршрутизатора и межсетевого экрана. Включает параметры ОФИС-2 и клиента администратора ЦУС, правила для USERS, SERVER и DMZ, NAT и прикладные сервисы.

## Применимость и статус

План подготовлен для ViPNet Coordinator VA через WebUI. Поведение фильтров сверено с документацией Coordinator HW/VA 4.5.8; точная версия установленного координатора пока не зафиксирована. Для Administrator используется база документации 4.6.11.

Таблицы описывают целевые параметры. Поле «Состояние: Включено» означает, какое состояние нужно выставить; оно не подтверждает, что правило уже применено и проверено. Скриншоты показывают отдельные этапы настройки и могут отличаться от итогового плана. Неизвестные адреса и порты вынесены в выключенные шаблоны в конце гайда.

## Схема стенда

ОФИС-1 обслуживает три отдельные подсети. На обычных пользовательских машинах ViPNet Client отсутствует; он установлен у администратора ЦУС. ОФИС-2 подключается через свой координатор; ограничения межофисного туннеля пока не настраиваем.

| Зона | Подсеть или адрес | Назначение | Интерфейс координатора |
| --- | --- | --- | --- |
| SERVER | 192.168.0.0/24 | ALD Pro, СЗИ, файловые ресурсы | Уточнить |
| USERS | 192.168.1.0/24 | Пользовательские машины | eth2 |
| DMZ | 172.16.0.0/24 | Веб-сервер и будущая почтовая инфраструктура | Уточнить |
| WAN | 10.228.228.202 | Эмуляция адреса провайдера на стенде | eth0 |
| Шлюз провайдера | 10.228.228.1 | Следующий узел для маршрута по умолчанию | Через eth0 |

| Узел или служба | Адрес | Статус |
| --- | --- | --- |
| Координатор в USERS | 192.168.1.1 | Согласованный адрес шлюза, DNS, NTP и DHCP |
| Координатор в DMZ | 172.16.0.1 | Согласованный адрес шлюза, DNS и NTP |
| Координатор в SERVER | По плану 192.168.0.1 | В текущем тесте DNS использовался 192.168.0.101; пользователь подтвердил этот адрес |
| Веб-сервер DMZ | 172.16.0.10 | Выбран для веб-публикации |
| Почтовый сервер DMZ | 172.16.0.12 | Предварительный адрес; наличие веб-почты ещё подтвердить |
| Релей Kaspersky в DMZ | Пока неизвестен | Отдельный узел; адрес не подменять адресом почтового сервера |

10.228.228.202 — частный адрес лабораторной сети. Само правило DNAT на нём не обеспечивает публикацию в настоящем интернете.

## Передача дистрибутивов ключей по TFTP

Передачу выполнять в изолированном сегменте или при прямом подключении: TFTP не шифрует файл. Дистрибутив ключей и его пароль хранить отдельно от гайда.

1. Использовать аварийный IP-адрес координатора: `169.254.241.1`.
2. На компьютере с ЦУС установить IP-адрес `169.254.241.5` и включить клиент TFTP.
3. Подключить адаптеры координатора и компьютера с ЦУС к одной виртуальной или физической сети.
4. Передать файл дистрибутива ключей `.dst`:

```cmd
tftp -i 169.254.241.1 PUT имя_файла.dst
```

## Настройка в WebUI

Сначала создаём группы адресов, затем настраиваем фильтры и NAT. Перед применением изменений сохраняем текущую конфигурацию и проверяем доступ к управлению координатором. При потере нужного доступа возвращаем изменённые правила к сохранённым параметрам через независимый канал управления.

## Группы адресов

### NAT_EXTERNAL

Группа содержит все IP-адреса, кроме перечисленных внутренних подсетей. В назначениях SNAT она исключает подмену адресов при обмене между внутренними подсетями; интерфейс выхода определяется маршрутизацией.

NAT_EXTERNAL не является привязкой к eth0. При добавлении других внутренних подсетей состав исключений нужно пересмотреть.

| Поле | Значение |
| --- | --- |
| Имя объекта | NAT_EXTERNAL |
| Состав | Все объекты |
| Исключения | 192.168.0.0/255.255.255.0; 192.168.1.0/255.255.255.0; 172.16.0.0/255.255.255.0 |

![Состав группы NAT_EXTERNAL](image-3.png)

### LAN

Группа объединяет подсети SERVER и USERS для использования в правилах одним источником, например в SNAT и локальных разрешениях DNS/NTP. DMZ учитывается отдельно, чтобы задавать для неё собственные правила.

| Поле | Значение |
| --- | --- |
| Имя объекта | LAN |
| Состав | 192.168.0.0/255.255.255.0; 192.168.1.0/255.255.255.0 |
| Исключения | Нет |

![Группа LAN: подсети SERVER и USERS без DMZ](image-2.png)

#### Сверка локальных фильтров

Сводный скриншот содержит промежуточные имена: у одной строки NTP_DMZ для LAN выбрана группа DNS, а у DNS-SERVER-USERS указан UDP 67 → 67. Проверять нужно фактические источники, назначения и протоколы; имена и дубли привести в соответствие таблицам выше, сохраняя нужные службы.

Штатные разрешения DHCP оставить для локального DHCP-сервера. Отдельный DHCP-relay не используется. Фильтры исходящих DNS/NTP-запросов координатора нужны для его обращений к вышестоящим серверам; они не заменяют разрешения клиентов к координатору.

### Транзитные фильтры открытой сети

#### План доступа USERS

Источники пользовательских соединений — подсеть USERS 192.168.1.0/24. Выбранная модель разрешает доступ ко всей подсети SERVER с запретом выбранных административных портов; для DMZ используются отдельные разрешения на веб и почту. Это план настройки: наличие таблиц не подтверждает применение всех правил на координаторе.

Правила ниже перечислены в порядке размещения. Default transit rule остаётся последним. Ответные пакеты разрешённых соединений пропускаются автоматически.

##### USERS_DENY_SERVER_ADMIN

Ограничивает доступ из USERS к стандартным портам удалённого администрирования серверов. Запрет SSH одновременно ограничивает SFTP; сервисы на нестандартных портах этим списком не перекрываются.

| Поле | Значение |
| --- | --- |
| Название | USERS_DENY_SERVER_ADMIN |
| Состояние | Включено |
| Действие | Блокировать трафик |
| Источники | 192.168.1.0/24 — USERS |
| Назначения | 192.168.0.0/24 — SERVER |
| Протоколы | TCP: порты назначения 22, 23, 3389, 5900, 5985, 5986; UDP: порт назначения 3389 |
| Порты источника | Любые |
| Расписание | Всегда |
| Порядок | Выше USERS_SERVER_ALLOW и других общих разрешений USERS → SERVER |

##### USERS_SERVER_ALLOW

По выбранному плану разрешает USERS обращаться к ALD Pro, СЗИ и файловым ресурсам всей серверной подсети. Выбранные административные порты блокируются предыдущим правилом.

| Поле | Значение |
| --- | --- |
| Название | USERS_SERVER_ALLOW |
| Состояние | Включено |
| Действие | Пропускать трафик |
| Источники | 192.168.1.0/24 — USERS |
| Назначения | 192.168.0.0/24 — SERVER |
| Протоколы | Все |
| Порты источника | Любые |
| Расписание | Всегда |
| Порядок | После USERS_DENY_SERVER_ADMIN, выше Default transit rule |

#### План доступа DMZ

Из DMZ разрешаем ответы на разрешённые обращения к веб-серверу и исходящий веб-доступ самого сервера. Новые соединения в SERVER и USERS запрещаем. Необходимые исключения для почты или доменных служб в дальнейшем размещаются выше запретов и ограничиваются конкретными узлами и портами.

##### WEB_DMZ_IN

Разрешает внешние подключения к веб-серверу после DNAT_WEB. Поэтому в назначении указан внутренний адрес 172.16.0.10. На имеющемся снимке редактора этого фильтра заданы только порты: источники и назначение необходимо проверить перед применением.

| Поле | Значение |
| --- | --- |
| Название | WEB_DMZ_IN |
| Состояние | Включено |
| Действие | Пропускать трафик |
| Источники | Группа NAT_EXTERNAL |
| Назначения | 172.16.0.10 — веб-сервер в DMZ |
| Протоколы | TCP: порты назначения 80 и 443, задать явно |
| Порты источника | Любые |
| Расписание | Всегда |
| Порядок | Выше Default transit rule и общих запретов внешних подключений |

Это публикация в лабораторной внешней сети через адрес 10.228.228.202. Доступ из настоящего интернета зависит от адресации и маршрутизации провайдера.

##### DMZ_WEB_OUT

Разрешает веб-серверу исходящие HTTP/HTTPS-соединения, в том числе загрузку обновлений. Назначение NAT_EXTERNAL не ограничивает доступ только репозиториями обновлений.

| Поле | Значение |
| --- | --- |
| Название | DMZ_WEB_OUT |
| Состояние | Включено |
| Действие | Пропускать трафик |
| Источники | 172.16.0.10 — веб-сервер в DMZ |
| Назначения | Группа NAT_EXTERNAL |
| Протоколы | TCP: порты назначения 80 и 443, задать явно |
| Порты источника | Любые |
| Расписание | Всегда |
| Порядок | Выше Default transit rule |

Для выхода используется SNAT_DMZ_WAN. Когда появится почтовый сервер 172.16.0.12, его можно добавить отдельным источником или аналогичным правилом. Порт 8080 здесь не открываем: он согласован только для USERS_WEB_OUT.

##### DMZ_DENY_SERVER

Запрещает серверам DMZ самостоятельно устанавливать соединения с SERVER. Ответы на разрешённые соединения пропускаются автоматически.

| Поле | Значение |
| --- | --- |
| Название | DMZ_DENY_SERVER |
| Состояние | Включено |
| Действие | Блокировать трафик |
| Источники | 172.16.0.0/24 — DMZ |
| Назначения | 192.168.0.0/24 — SERVER |
| Протоколы | Все |
| Порты источника | Любые |
| Расписание | Всегда |
| Порядок | Ниже согласованных точечных разрешений DMZ → SERVER, выше общих разрешений и Default transit rule |

##### DMZ_DENY_USERS

Запрещает новые подключения из DMZ к пользовательским машинам. Для чтения почты пользователь сам обращается к почтовому серверу или веб-почте; общее разрешение DMZ → USERS для этого не требуется.

| Поле | Значение |
| --- | --- |
| Название | DMZ_DENY_USERS |
| Состояние | Включено |
| Действие | Блокировать трафик |
| Источники | 172.16.0.0/24 — DMZ |
| Назначения | 192.168.1.0/24 — USERS |
| Протоколы | Все |
| Порты источника | Любые |
| Расписание | Всегда |
| Порядок | Ниже согласованных точечных исключений DMZ → USERS, выше общих разрешений и Default transit rule |

Оба запрета явно фиксируют изоляцию DMZ. В отсутствие разрешающих исключений тот же трафик уже блокируется Default transit rule.

#### План доступа SERVER

Подсеть SERVER — 192.168.0.0/24. Ответы серверам на разрешённые запросы USERS проходят автоматически. Если сервер СЗИ сам начинает соединение с агентом, требуется отдельное разрешение SERVER → USERS: выключенная форма SERVER_SZI_TO_USERS находится в конце гайда.

##### SERVER_WEB_OUT

Разрешает серверной подсети исходящий веб-доступ, в том числе к репозиториям и серверам обновлений СЗИ. Правило не ограничено только обновлениями: для этого потребовался бы отдельный список назначений.

| Поле | Значение |
| --- | --- |
| Название | SERVER_WEB_OUT |
| Состояние | Включено |
| Действие | Пропускать трафик |
| Источники | 192.168.0.0/24 — SERVER |
| Назначения | Группа NAT_EXTERNAL |
| Протоколы | TCP: порты назначения 80 и 443, задать явно |
| Порты источника | Любые |
| Расписание | Всегда |
| Порядок | Выше Default transit rule |

Для выхода используется SNAT_LAN_WAN. Новые соединения SERVER → USERS и SERVER → DMZ без отдельных разрешений остаются закрыты Default transit rule. Администрирование DMZ можно оформить по шаблону SERVER_ADMIN_TO_DMZ для конкретной административной машины.

Трафик между машинами одной подсети обычно проходит напрямую через коммутатор и не фильтруется координатором. Это касается, например, обмена между двумя серверами в SERVER или между почтовым релеем и сервером ящиков внутри DMZ.

#### Последнее правило и порядок обработки

Первое совпавшее правило определяет результат. В целевом плане сначала располагается USERS_DENY_SERVER_ADMIN, затем USERS_SERVER_ALLOW; точечные исключения из DMZ при их появлении ставятся выше DMZ_DENY_SERVER и DMZ_DENY_USERS. Остальные разрешения не пересекаются по источникам и назначениям. Встроенный запрет всегда остаётся последним.

| Поле | Значение |
| --- | --- |
| Название | Default transit rule |
| Состояние | Включено |
| Действие | Блокировать трафик |
| Источники | Все |
| Назначения | Все |
| Протоколы | Все |
| Порты источника | Любые |
| Расписание | Всегда |
| Порядок | Последнее встроенное правило; оставить без изменений |

#### Связанные настройки

- DNS и NTP самого координатора регулируются существующими локальными фильтрами; переносить их в транзитные правила не требуется.
- Для ALD Pro необходимо отдельно настроить разрешение внутренних доменных имён.
- Если СЗИ инициирует новое подключение к рабочей станции, нужен отдельный набор правил SERVER → USERS; разрешение USERS → SERVER такого подключения не открывает.
- Почтовой релей Kaspersky в DMZ рассматривается отдельно: его адрес и путь к серверу хранения почтовых ящиков ещё не определены. Письма передаются почтовому серверу, а пользовательский доступ к ящикам или веб-почте задаётся отдельными правилами.
- Формы для новых запретов находятся в разделе «Шаблоны правил МЭ» в самом конце заметок.

## Трансляция адресов NAT

### SNAT_LAN_WAN

SNAT_LAN_WAN обеспечивает выход SERVER и USERS во внешнюю сеть, заменяя их адреса адресом исходящего интерфейса координатора.

Правило ограничено группой LAN, исключает внутренние назначения и не публикует входящие сервисы. Для DMZ предусмотрено отдельное SNAT_DMZ_WAN, чтобы управлять её трансляцией отдельно.

Безопасность и изоляцию зон обеспечивают фильтры МЭ; сам SNAT разграничение доступа не заменяет.

| Поле | Значение |
| --- | --- |
| Название | SNAT_LAN_WAN |
| Состояние | Включено |
| Заменять адрес источника | Включено → адрес исходящего интерфейса (определяется автоматически) |
| Заменять адрес назначения | Выключено |
| Заменять порт назначения | Выключено |
| Источники | Группа LAN |
| Назначения | Группа NAT_EXTERNAL |
| Протоколы | Все |
| Порты источника | Любые |
| Расписание | Всегда |

![SNAT_LAN_WAN: трансляция источников из LAN при выходе во внешнюю сеть](image-4.png)

### SNAT_DMZ_WAN

SNAT_DMZ_WAN обеспечивает исходящие подключения серверов DMZ, например для загрузки обновлений. Отдельное правило позволяет управлять их трансляцией независимо от LAN; разрешённые подключения определяются фильтрами МЭ.

| Заменять адрес назначения | Выключено |

### DNAT_WEB

DNAT_WEB перенаправляет входящие веб-подключения с внешнего адреса 10.228.228.202 на сервер 172.16.0.10 в DMZ, сохраняя порт назначения и адрес клиента. Для публикации также нужен разрешающий транзитный фильтр; обратная трансляция ответов выполняется автоматически.

Целевой набор для публикации — TCP 80 и 443. На старом скриншоте выбраны группы HTTP и HTTPS. Так как группа HTTP для USERS включает также 8080, в DNAT_WEB порты нужно задать явно или использовать отдельную группу только с 80 и 443. Состав ранее сохранённого правила ещё проверить.

| Поле | Значение |
| --- | --- |
| Название | DNAT_WEB |
| Состояние | Включено |
| Заменять адрес источника | Выключено |
| Заменять адрес назначения | Включено → 172.16.0.10 |
| Заменять порт назначения | Выключено — сохраняется исходный 80 или 443 |
| Источники | Все |
| Назначения | 10.228.228.202 — внешний IP координатора на eth0 |
| Протоколы | TCP: порты назначения 80 и 443, задать явно |
| Порты источника | Любые |
| Расписание | Всегда |

| Вес | 1 |

## Прикладные сервисы

Здесь зафиксированы согласованные параметры и состояние служб по показанным экранам. С Linux получен успешный ответ DNS через 192.168.0.101; полный набор проверок, включая оба транспорта DNS, синхронизацию NTP и выдачу DHCP-адресов, ещё не завершён.

### NTP-сервер

Координатор используется как источник времени для внутренних машин. Включение службы видно на скриншоте; синхронизацию с вышестоящими источниками ещё нужно проверить.

| Поле | Значение |
| --- | --- |
| Состояние на показанном экране | NTP-сервер включён |
| Тип добавляемого источника | Сервер |
| IP-адрес или DNS-имя ручного источника | Пока не задан: поле на скриншоте пустое |
| NTP-адрес для клиентов USERS | 192.168.1.1 |
| Изолированный режим (orphan) | Состояние не проверено; настройки на показанном экране нет |
| Доступ клиентов к службе | Локальные фильтры открытой сети, UDP: порт назначения 123 |

Для настройки orphan нужно уточнить версию координатора. У Coordinator VA также нужно проверить, что NTP и гипервизор не корректируют время одновременно.

![NTP-сервер включён; адрес добавляемого вручную источника ещё не заполнен](screenshots/21-office-ntp-sources.png)

### DNS-сервер

Клиенты обращаются к DNS координатора, а он пересылает запросы во внешнюю сеть. Для пересылки выбраны адреса режима «Безопасный» [Яндекс DNS](https://dns.yandex.ru/), который фильтрует опасные сайты.

| Поле | Значение |
| --- | --- |
| Состояние на показанном экране | DNS-сервер включён |
| DNS-сервер пересылки 1 | 77.88.8.88 |
| Доменная зона для сервера 1 | Оставить пустой |
| DNS-сервер пересылки 2 | 77.88.8.2 |
| Доменная зона для сервера 2 | Оставить пустой |
| DNS-адрес для клиентов USERS | 192.168.1.1 |
| Доступ клиентов к службе | Локальные фильтры открытой сети, UDP/TCP: порт назначения 53 |

Адреса пересылки добавляются двумя отдельными записями. Параметры согласованы; успешный ответ через 192.168.0.101 не подтверждает, что использовались именно эти вышестоящие серверы. При развёртывании ALD Pro доменным клиентам нужно обеспечить разрешение внутренних имён через DNS домена: выдавать его адреса или настроить пересылку соответствующей доменной зоны на координаторе.

![Окно добавления DNS-сервера пересылки и доменной зоны до заполнения](screenshots/22-office-dns-forwarder-dialog.png)

### DHCP-сервер

#### Подсеть USERS

DHCP выдаёт пользовательским машинам адреса и параметры сети. Настройка выполняется через «Добавить подсеть»: выбрать тип «Локальная» и интерфейс eth2.

| Поле | Значение |
| --- | --- |
| Подсеть | USERS — 192.168.1.0/24 |
| Тип подсети | Локальная |
| Интерфейс | eth2 |
| Адрес интерфейса координатора | 192.168.1.1/24, статический |
| Маска подсети | 255.255.255.0 |
| Предложенный диапазон выдачи | 192.168.1.100–192.168.1.200 |
| Шлюз | 192.168.1.1 |
| DNS-сервер, передаваемый клиентам | 192.168.1.1 |
| NTP-сервер, передаваемый клиентам | 192.168.1.1 |
| Время аренды | Пока по умолчанию |
| Состояние на исходном экране | DHCP-сервер выключен; подсети ещё не добавлены |
| Проверка после настройки | Включение службы и выдача адресов пока не подтверждены |

Шлюз, DNS и NTP задаются для добавленной подсети USERS. Перед включением проверить, что предложенный диапазон свободен от статических адресов и в сегменте нет другого DHCP-сервера. DHCP для SERVER и DMZ пока не настраивали.

![Исходный экран DHCP: сервер выключен, в списке только Root](screenshots/23-office-dhcp-initial.png)

#### DHCP-relay

Не настраиваем: DHCP-адреса выдаёт сам координатор в напрямую подключённые подсети; ретрансляция запросов к отдельному DHCP-серверу не используется.

## Проверка после настройки

| Проверка | Что должно получиться |
| --- | --- |
| DNS из USERS к 192.168.1.1 по UDP и TCP | Координатор отвечает на запросы; обе проверки выполняются отдельно |
| DNS из SERVER к текущему адресу 192.168.0.101 | Для корректного имени получен успешный ответ; поддержку обоих транспортов ещё подтвердить |
| DNS и NTP из 172.16.0.10 к координатору в DMZ | Разрешены только необходимые службы; NTP-клиент показывает выбранный источник и синхронизацию |
| DHCP в USERS | Выдан адрес из согласованного пула и нужные шлюз, DNS и NTP |
| USERS → SERVER | Работают необходимые ALD Pro, СЗИ и файловые службы; выбранные административные порты блокируются |
| USERS → 172.16.0.10 | Открываются HTTP/HTTPS при запущенном веб-сервере |
| Внешний стенд → 10.228.228.202 на 80/443 | DNAT и WEB_DMZ_IN доставляют запрос веб-серверу; 8080 в публикацию не входит |
| DMZ → SERVER и USERS, новые соединения | Блокируются, кроме отдельно согласованных исключений |
| SERVER и 172.16.0.10 → внешние веб-ресурсы | Работают HTTP/HTTPS через соответствующий SNAT |

Пример отдельных проверок DNS с Linux в текущем SERVER-сегменте:

```bash
dig @192.168.0.101 ya.ru A +notcp +ignore +time=3 +tries=1
dig @192.168.0.101 ya.ru A +tcp +time=3 +tries=1
```

На ранней проверке имя `ya,ru` с запятой дало NXDOMAIN. После исправления на `ya.ru` получен NOERROR; по скриншоту нельзя установить, какой транспорт использовался. Для USERS в этих командах указать 192.168.1.1.

Отказ подключения сам по себе не доказывает срабатывание МЭ: служба может быть остановлена или закрыта на хосте. Для спорных случаев сверять источник, назначение, порт и время попытки с журналом координатора. Результаты новых правил пока не зафиксированы.

## Шаблоны правил МЭ

Шаблоны предназначены для подготовки новых правил. Перед включением заполнить источники, назначения и порты; состояние шаблона не означает, что правило уже создано на координаторе.

### Запрет выбранных портов

| Поле | Значение |
| --- | --- |
| Раздел | Транзитные фильтры открытой сети |
| Название | `DENY_<ИСТОЧНИК>_<НАЗНАЧЕНИЕ>_<СЕРВИС>` |
| Состояние | Выключено — включить после заполнения параметров |
| Действие | Блокировать трафик |
| Источники | `<IP, подсеть или группа IP-адресов источника>` |
| Назначения | `<IP сервера, подсеть или группа IP-адресов назначения>` |
| Протоколы | `<TCP и/или UDP, порты назначения или диапазоны>` |
| Порты источника | Любые, если для сервиса не требуется иное |
| Расписание | Всегда |
| Порядок | Выше общего разрешающего правила для того же направления |

В текущем плане USERS → SERVER источником является 192.168.1.0/24, назначением — 192.168.0.0/24. При использовании общего разрешения выбранные запреты должны срабатывать раньше него.

Примеры стандартных портов удалённого администрирования для заполнения шаблона:

| Сервис | Протокол | Порт назначения |
| --- | --- | --- |
| RDP | TCP и UDP | 3389 |
| Telnet | TCP | 23 |
| SSH/SFTP | TCP | 22 |
| WinRM | TCP | 5985 и 5986 |
| VNC, стандартный порт | TCP | 5900 |

Это примеры ограничений административного доступа. Они не перекрывают все опасные сервисы: приложения могут использовать другие порты, включая 443. Запрет SSH одновременно ограничит SFTP; учитывать это при выборе разрешённых пользовательских сервисов.

Порты RDP и Telnet сверены с [перечнем служб Microsoft](https://learn.microsoft.com/en-us/troubleshoot/windows-server/networking/service-overview-and-network-port-requirements), WinRM — с [документацией PowerShell Remoting](https://learn.microsoft.com/en-us/powershell/scripting/security/remoting/winrm-security).

### Подключения СЗИ к рабочим станциям

Форма для каждого продукта отдельно. Нужна только для соединений, которые начинает сервер СЗИ; ответы на запросы агентов из USERS не требуют обратного разрешения.

| Поле | Значение |
| --- | --- |
| Раздел | Транзитные фильтры открытой сети |
| Название | SERVER_SZI_TO_USERS |
| Состояние | Выключено — заполнить адрес и порты по документации конкретного СЗИ |
| Действие | Пропускать трафик |
| Источники | `<IP сервера конкретного СЗИ в SERVER>` |
| Назначения | 192.168.1.0/24 — USERS; при возможности сузить до машин с агентом |
| Протоколы | `<TCP и/или UDP, необходимые порты назначения агента>` |
| Порты источника | Любые, если документация продукта не требует иного |
| Расписание | Всегда |
| Порядок | Выше Default transit rule и общего запрета SERVER → USERS, если он добавлен |

### Администрирование серверов DMZ

Для выделенной машины администратора в SERVER. Не открывать административные службы всей пользовательской подсети.

| Поле | Значение |
| --- | --- |
| Раздел | Транзитные фильтры открытой сети |
| Название | SERVER_ADMIN_TO_DMZ |
| Состояние | Выключено — заполнить адреса и выбрать необходимую службу |
| Действие | Пропускать трафик |
| Источники | `<IP административной машины в SERVER>` |
| Назначения | `<IP администрируемого сервера в DMZ>` |
| Протоколы | `<протокол и порт управления; например TCP 22 для SSH>` |
| Порты источника | Любые |
| Расписание | Всегда или отдельное согласованное окно администрирования |
| Порядок | Выше Default transit rule и общего запрета SERVER → DMZ, если он добавлен |

### Приём почты внешним релеем

Адрес релея Kaspersky пока неизвестен. Этот фильтр используется вместе с отдельным DNAT для SMTP на адрес релея; DNAT_WEB его не заменяет. Точный продукт и схему доставки нужно подтвердить.

| Поле | Значение |
| --- | --- |
| Раздел | Транзитные фильтры открытой сети |
| Название | MAIL_RELAY_IN |
| Состояние | Выключено — сначала определить адрес релея и настроить DNAT для SMTP |
| Действие | Пропускать трафик |
| Источники | Группа NAT_EXTERNAL; при приёме только от вышестоящего шлюза указать его IP |
| Назначения | `<внутренний IP релея Kaspersky в DMZ после DNAT>` |
| Протоколы | TCP: порт назначения 25 для приёма межсерверного SMTP; при изменении службы сверить фактический порт |
| Порты источника | Любые |
| Расписание | Всегда |
| Порядок | Выше Default transit rule и общих запретов внешних подключений |

### Передача почты от релея серверу ящиков

Релей передаёт сообщения почтовому серверу. Если оба находятся в 172.16.0.0/24 и обмениваются напрямую, правило на координаторе этот обмен не контролирует — ограничения задаются на хостах или через отдельные сегменты.

| Поле | Значение |
| --- | --- |
| Раздел | Транзитные фильтры открытой сети — только если обмен проходит через координатор |
| Название | DMZ_RELAY_TO_MAIL |
| Состояние | Выключено — подтвердить размещение сервера ящиков и путь трафика |
| Действие | Пропускать трафик |
| Источники | `<IP релея Kaspersky в DMZ>` |
| Назначения | `<IP сервера почтовых ящиков>` |
| Протоколы | TCP: фактически настроенный порт входящего SMTP почтового сервера |
| Порты источника | Любые |
| Расписание | Всегда |
| Порядок | Выше DMZ_DENY_SERVER, если сервер ящиков расположен в SERVER; в остальных случаях выше соответствующего запрета и Default transit rule |

### Исходящая почта из DMZ

Применяется к узлу, который действительно отправляет почту наружу. Для доставки через внешний SMTP-шлюз разрешение сужается до адреса этого шлюза и его фактического порта.

| Поле | Значение |
| --- | --- |
| Раздел | Транзитные фильтры открытой сети |
| Название | DMZ_MAIL_OUT |
| Состояние | Выключено — определить отправляющий узел и способ отправки |
| Действие | Пропускать трафик |
| Источники | `<IP исходящего почтового сервера или релея в DMZ>` |
| Назначения | `<IP внешнего SMTP-шлюза>`; для прямой доставки на MX — группа NAT_EXTERNAL |
| Протоколы | TCP: фактический порт SMTP-шлюза; для прямой доставки на MX — порт назначения 25 |
| Порты источника | Любые |
| Расписание | Всегда |
| Порядок | Выше Default transit rule |

Для исходящей почты также используется SNAT_DMZ_WAN. Разрешение SMTP на МЭ не заменяет настройку допустимых отправителей и направлений пересылки на самом релее.
